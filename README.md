# 여행영어 목업 (Mockup)

`prd.md` v2를 기준으로 만든 **동작하는 HTML 목업**입니다. 화면 모양뿐 아니라 버튼을 눌렀을 때의 흐름, 문장 수·일정표 계산, 영어 듣기(TTS)까지 실제로 확인할 수 있습니다.

> 이 목업은 확인용입니다. 로그인, AI 생성, 웹 검색은 흉내만 내며 서버나 데이터베이스에 연결되지 않습니다. 새로고침하면 처음 상태로 돌아갑니다.

---

## 1. 실행 방법

1. `index.html`을 Chrome 또는 Edge로 엽니다. (더블클릭하면 됩니다. 설치나 서버가 필요 없습니다.)
2. 왼쪽 메뉴에서 화면을 고르거나, 화면 안의 버튼을 눌러 흐름을 따라갑니다.

**주소로 특정 화면 바로 열기**: 주소 뒤에 `#화면ID`를 붙입니다.

```
index.html#u-home     → 홈
index.html#u-study    → 학습 카드
index.html#a-jobs     → 생성 작업 모니터
```

**참고**
- 글꼴(Pretendard, Fraunces, JetBrains Mono)은 인터넷에서 불러옵니다. 오프라인이면 시스템 글꼴로 보입니다.
- TTS는 브라우저 음성 합성 기능을 씁니다. Chrome·Edge에서 가장 잘 동작하며, 영어 음성이 없는 브라우저에서는 "듣기를 지원하지 않아요" 안내가 나옵니다.

## 2. 파일 구성

| 파일 | 내용 |
|------|------|
| `index.html` | 전체 틀 (왼쪽 메뉴, 위쪽 상태 표시줄, 오른쪽 화면 영역) |
| `styles.css` | 디자인 (색상, 글꼴, 휴대폰 틀, 관리자 창, 카드 뒤집기 애니메이션 등) |
| `app.js` | 화면 그리기, 버튼 동작, 계산 규칙, 생성 흐름, TTS |
| `data.js` | 고정 데이터 (공통 상황 문장 30개, 장소별 문장 틀, 뉴욕·보스턴 장소, 관리자용 가짜 운영 데이터) |

## 3. 화면 구성

### 전체 배치

```
┌──────────────┬─────────────────────────────────────────────┐
│ 왼쪽 메뉴     │ 위쪽: 화면 번호 · 이름 · 오늘 날짜 · 여행 상태 │
│ (사용자 10개  ├──────────────────────────┬──────────────────┤
│  관리자 4개)  │  사용자 화면: 휴대폰 틀    │ 설명 카드         │
│              │  관리자 화면: 브라우저 창  │ · 관련 요구사항   │
├──────────────┤                          │ · 해 볼 것        │
│ 데모 조작     │                          │ · 데모 버튼       │
│ 패널         │                          │ · 계산 결과       │
└──────────────┴──────────────────────────┴──────────────────┘
```

- 관리자 화면은 창을 넓게 쓰기 위해 설명 카드가 창 아래에 나옵니다.

### 사용자 화면 (10개)

| 번호 | 화면 | 주요 확인 내용 | 관련 요구사항 |
|------|------|----------------|---------------|
| SCR-01 | 로그인 | 구글 로그인 흉내, 로그아웃 | FR-AUTH-01·02 |
| SCR-02 | 여행 입력 | 도시 추가·삭제(1~5곳), 입력 오류, 영어권 아닌 나라 안내, 짧은 학습 경고, 기존 여행 보관 확인 | FR-TRIP-01·03·04·05 |
| SCR-03 | 생성 중 · 실패 | 진행 단계 표시, 실패와 다시 시도, 3번 연속 실패 안내, 15분 멈춤 처리 | FR-GEN-01·02·03 |
| SCR-04 | 보고서 · 장소 선택 | 도시별 기본 장소와 후보, 최대 수 제한, 후보로 바꾸기, 다시 생성(최대 3번), 출처 표시 | FR-REPORT-01·02·03, FR-PLACE-01 |
| SCR-05 | 추천 방문 순서 | 날짜별 장소 배치, 도착일·이동일·귀국일, 자유 일정, 검증 결과, 문장 수 요약 | FR-ROUTE-01, FR-SENT-02 |
| SCR-06 | 홈 | D-N / 여행 N일차 / 종료 요약, 오늘 학습, 완료율, 다가오는 일정 | FR-STUDY-03, FR-END-01 |

| SCR-08 | 학습 카드 | 카드 뒤집기, 듣기(TTS), 속도 조절, 완료 조건, 날짜별 완료 가능 여부 | FR-STUDY-01·02·04 |
| SCR-09 | 문장 모음 | 공통 상황·장소별 문장, 문장마다 듣기, "문장 모음 전용" 표시 | FR-STUDY-05, FR-SENT-01 |
| SCR-06 | 여행 종료 요약 | 완료율, 학습한 문장 수, 완료한 날, 새 여행 만들기(이전 여행 보관) | FR-END-01, FR-TRIP-04 |

### 관리자 화면 (4개) — PRD 외 제안

PRD에는 관리자 화면이 정의되어 있지 않습니다. 운영에 필요할 것으로 보여 **제안용**으로 만들었으며, 메뉴와 화면에 "PRD 외 제안"으로 표시했습니다.

| 번호 | 화면 | 내용 |
|------|------|------|
| ADM-01 | 운영 지표 | PRD 2-2의 성공 지표 4개를 `stageAt` 기준으로 계산, 목표 달성 여부, 단계별 도달 수, 최근 실패 |
| ADM-02 | 생성 작업 모니터 | 생성 중·멈춤·실패 작업 목록, 15분 넘은 작업 강조, "실패로 처리" |
| ADM-03 | 공통 문장 관리 | 공통 상황 문장 30개 수정, 문장별 듣기, 저장 시 다음 문장 생성부터 반영 |
| ADM-04 | 사용자 · 여행 | 사용자별 현재 여행과 보관된 여행 |

## 4. 데모 조작 패널 (왼쪽 아래)

| 항목 | 설명 |
|------|------|
| 오늘 | 목업 안의 "오늘" 날짜를 바꿉니다. 여행 전·여행 중·종료 후 화면을 확인할 때 씁니다. |
| 날짜 빠른 버튼 | 가입일, 학습 시작, 출발 전날, 여행 첫날, 이동일, 종료 다음 날로 바로 이동 |
| AI 생성 실패 | 켜면 다음 AI 생성이 실패합니다. |
| 생성 멈춤 (응답 없음) | 켜면 생성이 끝나지 않고 "생성 중"에 멈춥니다. |
| 방문 순서 AI 규칙 위반 | 켜고 방문 순서를 만들면 "코드 규칙으로 배치했어요" 안내가 나옵니다. |
| TTS 미지원 브라우저 | 켜면 듣기 버튼 대신 미지원 안내가 나옵니다. |
| 짧은 학습 3일 | 여행 전 학습 3일 예시를 바로 만듭니다. (하루 10문장, 장소 문장은 여행 중 학습) |
| 당일 시작 0일 | 여행 당일부터 학습하는 예시를 바로 만듭니다. (모든 문장을 여행 중 학습) |
| 전체 초기화 | 처음 상태로 되돌립니다. |
| 접기 / 펼치기 | 패널을 접어 메뉴를 넓게 봅니다. |

화면별 설명 카드에도 그 화면 전용 데모 버튼이 있습니다. (예: "빈 날 오류 예시 넣기", "실패 화면 보기", "16분 경과시키기", "지난 날 일부를 완료로 채우기")

## 5. 추천 확인 순서

1. **기본 흐름**: 로그인 → 여행 입력(기본값 그대로) → 보고서 만들기 → 장소 하나 빼고 후보 체크 → 확정하기 → 방문 순서 확인 → 홈
2. **학습**: 데모 패널에서 "학습 시작" 날짜 선택 → 홈의 "오늘 학습 시작" → 카드를 모두 뒤집고 "듣기" → 학습 완료
3. **진도**: "여행 첫날"로 날짜 이동 → 홈이 "여행 1일차"로 바뀌는지, 일정표에 미완료가 표시되는지 확인
4. **예외**: SCR-03의 "실패 화면 보기", "멈춤 화면 보기" → "16분 경과시키기" → 다시 시도
5. **짧은 기간**: 데모 패널의 "짧은 학습 3일", "당일 시작 0일" → 방문 순서 요약과 오른쪽 계산 결과 확인
6. **종료**: 메뉴의 "여행 종료 요약" → 새 여행 만들기 → 관리자 "사용자 · 여행"에서 보관된 여행 확인

## 6. 목업에 구현된 계산 규칙

`app.js`의 `R` 객체에 PRD 규칙을 그대로 구현했습니다. 실제 개발 시 `shared/rules/`로 옮길 수 있는 형태입니다.

| 함수 | 규칙 | PRD |
|------|------|-----|
| `R.buildDays` | 날짜 종류(도착일·일반일·이동일·귀국일), 소속 도시, 하루 기본 장소 수 | FR-TRIP-02 |
| `R.cityBase` | 도시별 기본 장소 수 | FR-TRIP-02 |
| `R.validate` | 여행 입력 검사, 짧은 학습 경고 | FR-TRIP-01 |
| `R.kinds` | 여행 전 새 문장·복습·총복습 배치 | FR-SCHED-01 |
| `R.counts` | 장소당 문장 수, 전체 문장 수, 하루 학습량 (음수·0 경계 처리 포함) | FR-SENT-02 |
| `R.validateRoute` | 방문 순서 검증 (도시 일치, 하루 수 제한, 누락·중복 없음) | FR-ROUTE-01 |
| `R.placeByCode` | 코드 배치 (지역 이름 순 정렬 후 날짜 순서대로 채움) | FR-ROUTE-01 |
| `buildPlan` | 문장 목록과 일정표 생성, 여행 중 새 문장 배정, 자유 일정 판정 | FR-SCHED-01·02 |
| `progress` | 완료율 (자유 일정 제외) | FR-STUDY-03 |

**PRD 예시와 일치 확인 결과**

| 예시 | 입력 | 결과 |
|------|------|------|
| 기본 (예시 1) | 뉴욕 11/10~11/13, 보스턴 11/13~11/15, 학습 10/01, 장소 18곳 | 기본 장소 뉴욕 10·보스턴 8, 새 문장 학습일 29일, 전체 145문장, 하루 5문장, 7문장 7곳·6문장 11곳, 복습 9일·총복습 2일 |
| 짧은 학습 (예시 2) | 여행 전 3일 | 하루 10문장, 공통 30개는 여행 전, 장소 54개는 여행 중, 도착일 21문장 |
| 당일 시작 (예시 3) | 여행 전 0일 | 전체 84문장 모두 여행 중, 도착일 새 문장 21개, 길 묻기·쇼핑과 긴급 상황 10개는 문장 모음 전용 |

## 7. 실제 서비스와 다른 점

| 항목 | 목업 | 실제 서비스 (PRD·기술스택) |
|------|------|----------------------------|
| 로그인 | 버튼을 누르면 데모 사용자로 로그인 | Firebase Authentication (구글 로그인) |
| 보고서 | `data.js`의 뉴욕·보스턴 장소 사용. 다른 도시는 일반 이름으로 채움 | AI + 웹 검색 (AI-01) |
| 장소별 문장 | `data.js`의 문장 틀에 장소 이름·대표 메뉴를 넣어 만듦 | AI 생성 (AI-03) |
| 방문 순서 | 코드 배치 결과를 사용 | AI 제안 + 검증, 실패 시 코드 배치 (AI-02) |
| 생성 대기 | 단계마다 약 0.7초씩 진행 | Cloud Functions 백그라운드 처리 + Firestore 실시간 구독 |
| 데이터 저장 | 브라우저 메모리 (새로고침하면 초기화) | Cloud Firestore |
| 오늘 날짜 | 데모 패널에서 바꿀 수 있음 | 사용자 기기 날짜 (NFR-03) |
| 관리자 화면 | 가짜 운영 데이터 + 데모 여행 | PRD에 없음 (제안) |
