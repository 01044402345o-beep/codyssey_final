# 에이전트 교차검증 기록

한 사람(한 세션)이 검증하면 확증 편향이 생긴다. 그래서 **되돌리기 어렵거나 보안·개인정보에 닿는 변경**은
여러 **독립 에이전트**에게 서로 다른 각도로 같은 질문을 던지고, **영가설(기능이 실제로 아무것도 하지 않는다)을
기본값**으로 두고 반증하게 한다. 이 문서는 그 방식(규칙)과 지금까지의 실행 결과를 남긴다.

이 문서가 다루는 변경: **회원 탈퇴(FR-17)** 와 그 과정에서 도입한 **관리자 삭제·토큰 취소 경로**.
관련 제품 요구는 [product/requirements.md](../product/requirements.md) FR-17, 배포는 [deploy/DEPLOY_RUNBOOK.md](../deploy/DEPLOY_RUNBOOK.md) E.

## 1. 운영 규칙 (실제로 쓴 것)

| 규칙 | 내용 |
|---|---|
| 병렬 독립 | 각도를 겹치지 않게 나눈다. 같은 각도를 여러 번 넣으면 중복만 늘어난다 |
| 영가설 먼저 | "동작한다"를 가정하지 않는다. "동작하지 않는다"를 기본값으로 두고 반증을 시도한다 |
| 근거 강제 | `file:line` 과 실행한 명령·출력만 채택한다. 요약·추정은 채택하지 않는다 |
| 읽기 전용 | 에이전트는 **파일을 수정하지 않는다**(동시 편집 충돌 방지). 서버 기동·Playwright 금지(포트 충돌), 단위 테스트만 허용 |
| 형식 고정 | Claim / Hypotheses(대안가설) / Evidence / Verdict(FALSIFIED·NOT FALSIFIED·UNKNOWN) / Residual risk + 가장 강한 다음 검증 |
| 합성 | 두 각도 이상에서 수렴한 결함부터 고친다. 근거 없는 지적은 보류하고 `UNKNOWN` 으로 남긴다. 수정 뒤 같은 검사로 재검증 |
| 에이전트가 하지 않는 것 | 커밋·푸시·배포·머지, 실계정 로그인, 시크릿 취급 |

## 2. 실행 이력

### 라운드 1 — 회원 탈퇴(FR-17) 1차 · 에이전트 5

| # | 각도 | 핵심 발견 |
|---|---|---|
| ① | 서버 삭제 + Firestore 규칙 | 코드 경로·uid 결속·404(없는 문서=성공, 없는 DB=503) 구분은 안전. **규칙 테스트가 문자열 검사뿐**이라 `signedIn()` 을 약화한 변형을 못 잡음 |
| ② | 클라이언트 순서·경합 | **토큰이 비면 서버 삭제를 건너뛰고 계정만 삭제**(서버 문서 고아), 늦은 PUT 이 문서를 되살릴 창(미반증) |
| ③ | 데이터 완전성·페르소나 | **로그인 전 공용 칸(`cd_*`)이 안 지워짐**, 위 고아, 익명 계정 미삭제(도달 불가), `requires-recent-login` 일관성, 진행 중 생성 미취소 |
| ④ | 테스트 신뢰도(변이) | 테스트가 증명하는 것은 배선뿐. 규칙·FirestoreUserStore.delete·5xx·클라이언트 중단이 **미검증**. 변이 2종이 그대로 통과 |
| ⑤ | 보안·삭제권 | 고아(높음), **서버측(관리자) 삭제 경로 없음**(높음), 비원자적이라 되살아날 수 있음(중간), 미만료 토큰 창(중간) |

**수정(커밋)** — 결함 4건: (a) 토큰 없음도 실패로 보고 탈퇴 중단 (b) 공용 칸도 함께 삭제 (c) 예약 업로드 취소 + `pushPayload` 토큰 수령 뒤 uid/플래그 재확인 (d) `cancelGen()`.
**테스트 보강**: `FirestoreUserStore.delete` 요청 형태·404 성공·403→503, DELETE 스토어 장애 503, 규칙 **본문**(본인 uid·익명 거부) + **주석 제거 후** `allow` 확인, e2e 계정 칸+공용 칸 동시 폐기.

### 라운드 2 — 관리자 삭제·토큰 취소 경로 · 에이전트 4

목적: `POST /account/erase` (서비스 계정으로 토큰 취소 `validSince` + Firestore 문서 삭제 + Auth 계정 삭제, **최근 로그인 불필요**).

| # | 각도 | 핵심 발견 |
|---|---|---|
| ① | 관리자 경로 보안 | 교차 사용자 삭제 불가·시크릿 미노출은 안전. **자격증명 발급 실패가 AdminError 로 감싸지지 않아 500 으로 샘**, 스코프가 너무 넓음(`cloud-platform`), SA/프로젝트 불일치 무경고, `_missing` 판정이 과광 |
| ② | 클라이언트 분기·경합 | **2xx 를 무조건 성공으로 봄**(프록시 200 오인), **중단 경로가 서버 문서를 빈 값으로 덮음**(로컬을 먼저 지워서) — 가장 강한 지적. 재생성 경합·재로그인 유도는 반증(안전) |
| ③ | 테스트 신뢰도(변이) | 5xx 를 성공으로 삼키는 변형, `rate_limit` 제거, 404/405 분기 삭제, 토큰 상수화 — **모두 통과**(미검출) |
| ④ | 운영·문서·시크릿 | 키 노출 없음·`sync: false` 정상. 런북 E 에 **최소 권한 역할 없음**, 문서 6곳이 "서비스 계정 키를 쓰지 않는다"와 모순, `_token()` 500 재현, `google-auth` 미핀 |

**수정** — 결함 6건: (a) 자격증명 실패를 503 `admin_failed` 로 감쌈 (b) 클라이언트가 200 이어도 본문 계약(`erased:true`/`deleted:true`) 확인 (c) **로컬 삭제를 서버 확정 뒤로 이동**(중단 시 계정·기록 그대로) (d) `_missing` 좁힘 + 5xx 중단 테스트 (e) 스코프를 좁힘 (f) 문서 모순 6곳 + 런북 최소 권한 역할 + `google-auth` 핀.
**테스트 보강**: 토큰 실패 래핑, 중간 5xx 는 `accounts:delete` 전에 중단, 스코프, `_missing` 좁힘, `/account/erase` 레이트리밋, e2e **본문 계약 없는 200 은 성공 아님** + **중단 시 로컬 유지**.

> 라운드 1의 "로컬 먼저 삭제"는 재생성 방지에는 좋았지만, 라운드 2가 **중단 경로에서 서버 기록을 빈 값으로 덮는** 부작용을 찾아내 순서를 뒤집었다. 교차검증이 실제로 잡은 예다.

### 라운드 3 — 수정 뒤 재검증 + 문서 진실성 · 에이전트 5

목적: 라운드 2 **수정 자체**를 반증하고, **이 기록 문서의 주장**까지 감사한다.

| # | 각도 | 핵심 발견 |
|---|---|---|
| ① | 문서 진실성(메타) | 수치·sha·결함표·"안전" 목록은 대부분 사실. **"e2e 11종"은 오류(실제 12종)**, **FR-17 이 옛 순서(로컬 먼저)** 로 남아 코드와 모순 |
| ② | 수정 정합성 | 6건 수정은 실질적으로 맞고 행복 경로 회귀 없음. 남은 것: 폴백 경로의 재생성 창(문서 삭제 후 계정 삭제 전), `status===200` 엄격성, 스코프/IAM 온라인 검증 불가, 클라이언트 수정의 실행 검증 부재 |
| ③ | 데이터 완전성(모집단) | **다중 기기 + 미만료 토큰(≤1h)이 문서를 다시 만들 수 있음**(가장 큰 잔여 위험), 콘솔 등 외부 삭제 시 고아 문서, 메모리 `S.archived` 미정리, 익명 계정 미삭제 |
| ④ | 테스트 신뢰도(변이) | **`_missing` 가드를 없애도 통과**(없음이 아닌 400 을 성공으로 삼킴 → 토큰 미취소·문서 방치), 네트워크 오류 래핑 제거·`configured` 단락 제거도 통과. e2e 는 404/405·Authorization·순서 미검증 |
| ⑤ | 보안·스코프·시크릿 | **`identitytoolkit` 단독 스코프가 부족할 수 있음**(서비스 문서는 `firebase`/`cloud-platform` 만 광고) → 403 이면 관리자 경로가 아예 안 됨. 키 노출은 없음. `.gitignore` 에 Firebase 키 JSON 패턴 없음 |

**수정** — 결함 7건: (a) 스코프를 `firebase`+`identitytoolkit`+`datastore` 로(서비스/메서드 문서 두 출처 모두 커버) (b) `_missing` 가드 배선 테스트 추가(없음이 아닌 400 은 실패) (c) HTTP 가 아닌 오류도 `AdminError` 로 래핑 + 엔드포인트의 예상 못 한 예외도 503 (d) **FR-17 순서를 서버 우선으로 정정** (e) e2e 강화(404/405 폴백, `Authorization: Bearer` 확인, 순서 확인) (f) `.gitignore` 에 `*-firebase-adminsdk-*.json`·`serviceAccount*.json` 추가 (g) `configured()` 가 `client_email` 도 요구, 메모리 `S.archived` 정리, 경고 주석 정정.

### 라운드 4 — 다중 기기 재생성 차단(tombstone) · 사람 세션(구현+측정)

목적: 라운드 2·3 이 일관되게 지목한 **가장 큰 잔여 위험**(다른 기기의 미만료 ID 토큰이 `users/{uid}` 를 되살림)을 없앤다.

설계 선택: **요청마다 cancellation 조회** 대신 **탈퇴 흔적(tombstone)** — `POST /account/erase` 가 Firestore `deleted/{uid}`(uid·시각만)를 **가장 먼저** 쓰고, `PUT /user/state` 는 흔적이 있으면 **403 `account_deleted`** 로 거부한다. 화면은 그 응답을 탈퇴 완료로 보고 로컬을 비우고 로그아웃한다.

| # | 각도 | 판단 |
|---|---|---|
| ① | 새 결함면 | 요청당 조회는 왕복 비용이 크고 `verify_bearer` 마다 부르면 모든 쓰기가 관리자 읽기에 묶인다 → **tombstone + 인프로세스 캐시**(양성 1h·음성 60s) 채택 |
| ② | 순서 | 흔적을 **먼저** 쓴다. 토큰 취소·문서 삭제·계정 삭제가 도중 실패해도 재생성은 이미 막혀 있고 다시 시도할 수 있다 |
| ③ | 규칙·비용 | 흔적은 **서비스 계정**만 읽고 쓴다 → `firestore.rules` 변경 없음(관리자 접근은 규칙을 거치지 않는다), 배포도 규칙 단독 배포 그대로 |
| ④ | 실패 모드 | 흔적 조회 실패는 **통과(fail-open)** — 일시적 저장소 장애가 앱 전체 쓰기를 막지 않게. 다중 인스턴스에서 탈퇴 전파가 최대 60초 늦을 수 있다(단일 인스턴스 Render 에서는 즉시) |
| ⑤ | 개인정보 | 흔적은 uid·시각뿐 — 개인정보를 담지 않는다. 규칙이 막아 클라이언트는 읽을 수 없다 |

**구현**: `firebase_admin` — `write_tombstone`/`read_tombstone`/`is_erased`/`mark_erased`/`reset_cache`, `erase` 순서 변경(흔적→취소→문서→계정), `_call` 이 409(이미 있음)를 성공으로 처리. `main.py` — `PUT /user/state` 403 가드. `mockup/app.js` — `handleAccountDeleted`(403 `account_deleted` 시 정리·로그아웃), `accountClosed` 가드, `adoptAccount` 에서 초기화.

**검증(이 작업 트리, 사람 세션 실측)**: 백엔드 **218 통과**(+5: 흔적 순서·조회·캐시·fail-open·409), 탈퇴 e2e **21 통과**(+1: 403 을 받은 화면이 로컬 정리 후 로그인 화면).

| 17 | 메모리 `S.archived` 미정리 / `configured()` 가 `client_email` 미요구 | 낮음 | 3 | 정리·요구 추가 |

## 4. 반증되어 "안전"으로 남은 가설

남의 문서 삭제 불가(토큰 uid 결속 · `_UID` 정규식 · 경로 인용), 익명 403, 무토큰 401, 없는 문서=성공 / 없는 **DB**=503 구분, `write`→`create,update`+`delete` 분할이 쓰기 동작을 바꾸지 않음, 삭제+재생성으로 제한 우회 불가, 확인창 더블탭 차단, `pagehide`/`visibilitychange` 경로 차단, 복원 중 백그라운드 생성이 상태를 덮지 않음, IndexedDB·cookie·SW 없음, 관리자 경로가 토큰 없이 도달 불가, 시크릿이 응답·로그·`/health` 에 없음, 프로젝트 혼동 대상 아님(대상은 `FIREBASE_PROJECT_ID`), `eraseOnServer` 의 2xx/404/405/503 분류, 폴백 순서(규칙 삭제 → 로컬 → deleteUser).

## 5. 남은 위험 / 미검증 (정직하게)

- **다중 기기 + 미만료 토큰 재생성 창 — 라운드 4 에서 닫음(남은 구멍 있음)**: 탈퇴 흔적(`deleted/{uid}`)으로 `PUT /user/state` 를 403 `account_deleted` 로 거부한다(구현·검증 완료). 남은 구멍은 (a) 흔적 조회 실패 시 통과(fail-open), (b) 음성 캐시 60초 때문에 다중 인스턴스에서 탈퇴 전파가 최대 60초 늦을 수 있음, (c) 흔적 자체는 삭제되지 않고 남는다(정리는 관리자 몫). 실계정 왕복은 여전히 미관측.
- **폴백 경로는 흔적을 남기지 않는다**: 키가 없어 규칙 삭제 + 클라이언트 `deleteUser` 로 되돌아간 경로에는 흔적이 없으므로, 그 경우 다른 기기의 미만료 ID 토큰이 문서를 다시 만들 수 있다(종전과 같은 창). 흔적은 관리자 경로에서만 쓰인다.
- **실계정 왕복 미관측**: 로그인한 실제 계정의 `/user/state` 쓰기·삭제, `deleteUser`, 관리자 삭제 왕복은 이 환경에서 확인하지 못했다(FR-16·FR-17 "부분").
- **스코프·IAM 온라인 검증 불가**: 좁힌 스코프와 런북의 역할이 실제 API 를 통과하는지는 실제 자격증명이 필요하다. 틀리면 403 → `admin_failed` → 탈퇴가 막힌다(데이터 손실은 없음).
- **Firestore 규칙 실행 검증 불가**: Java 가 없어 에뮬레이터를 못 돌린다. CLI 컴파일 통과 + 정적 검사로 대체했다.
- **서비스 계정 실토큰 발급 미검증**: 관리자 테스트는 `_creds` 를 스텁한다. 실제 PEM 파싱·JWT 서명·토큰 교환은 확인하지 않았다.
- **관리자 키 미설정 시 폴백**: 키가 없으면 503 `admin_unavailable` → 규칙 삭제 + 클라이언트 `deleteUser` 로 되돌아간다. 이때 `requires-recent-login` 이면 계정이 남는다.
- **콘솔 등 외부 삭제 시 고아 문서**: 앱을 거치지 않고 Firebase 콘솔에서 계정을 지우면 `users/{uid}` 문서가 남고 지울 주체가 없다(관리자 배치·트리거 없음).
- **e2e 스텁의 한계**: 관리자 분기 검사는 `fetch`·`FirebaseAuth` 를 대체한 것이라 실제 요청 헤더·실제 `deleteUser`·`requires-recent-login` 은 보지 못한다(순서·토큰·본문 계약까지만 본다).
- **토큰 취소의 전파 지연**: `validSince` 는 갱신 토큰을 즉시 무효화하지만, 이미 발급된 ID 토큰은 만료(≤1h)까지 유효하다(위 첫 항목과 같은 원인).

## 6. 다음에 그대로 쓰는 프롬프트 템플릿

```
너는 적대적 검증자다. 저장소: <경로> (브랜치 <이름>).
규칙: 파일을 수정하지 마라. 서버를 띄우지 마라. Playwright 금지. 허용: 단위 테스트(<명령>).
영가설 먼저(기본값 = 기능이 실제로 아무것도 하지 않는다).
주장: "<검증할 한 문장>"
읽을 파일: <파일 목록>
다음을 모두 하라:
  1) 주장을 반증할 대안가설을 나열하고, 각각을 코드/실행으로 검사한다.
  2) 근거는 file:line 과 실제 명령 출력만 쓴다.
  3) 형식: Claim / Hypotheses / Evidence / Verdict(FALSIFIED·NOT FALSIFIED·UNKNOWN) / Residual risk + 가장 강한 다음 검증.
각도: <서버·규칙 | 클라이언트 경합 | 데이터 완전성·페르소나 | 테스트 신뢰도(변이) | 보안·삭제권 | 운영·문서·시크릿>
```

## 7. 주의

- 병렬 에이전트는 시간·토큰을 쓴다. 각도는 2~3개로 줄이는 편이 나을 때가 많다(서버 / 클라이언트 / 테스트 신뢰도가 최소 조합).
- 에이전트 지적을 그대로 코드에 넣지 않는다. 근거를 확인하고, 근거가 약하면 `UNKNOWN` 으로 남긴다.
- 에이전트의 **변이(mutation) 지적**은 특히 값이 크다. "틀린 코드가 통과하는 예"를 보여주므로, 그 자리에 테스트를 추가하면 회귀가 막힌다.
