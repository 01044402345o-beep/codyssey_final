배포 직후 3분 판정
Go · 제한 Go · No-Go

목적은 장애를 없애는 것이 아니라 장애가 났을 때 3분 안에 판단하고 되돌리는 것입니다. 아래 게이트를 통과하지 못하면 거기서 멈춥니다. 다음 단계로 넘어가지 않습니다. 왼쪽 위에서 아래로 내려가며, 각 게이트의 필드 값을 실제 응답에서 확인하세요.

GATEcurl -s https://<앱>.onrender.com/health | python3 -m json.tool

서비스명 codyssey-api — 실제 URL은 1장 자산 대장에서 채운 뒤 위 명령에 넣으세요.

G3

AI가 실제로 도나?

has_api_key · /generate → usable

서비스는 살아 있는데 AI 계층만 불완전한 구간입니다. 중단이 아니라 시연 축소입니다. 제한 GO = 샘플 UI 시연만 가능. AI·음성·자동 기억 검증 미완료 — 발표 가능 여부와 기술 검증 통과는 다릅니다.

has_api_key: false

화면이 붙고 기억이 도나?

화면 연결 · 전체 흐름 1회 · 기억 4단계

마지막 게이트. 화면은 같은 서비스에서 서빙되므로 기본 구성에서는 CORS 문제가 없습니다. 화면만 실패하면 백엔드 단독으로도 시연이 됩니다.

화면이 서버에 안 붙음
(?api= 외부 서버 · file:// · 서비스 중지)

복습 배지가 데모 기록으로만 뜸
제한 GO

입력 → 생성 → 카드 → 녹음 → 진도 통과

판정 3분기 — 게이트 결과가 모이는 곳

GO
게이트 전부 통과 · AI·음성 실동작 + 기억 4단계 확인
  • 프론트 연동 진행, 전체 흐름 시연
  • mock: false · usable: "ok" 를 화면에서 확인. 기억은 데모 기록이 아닌 실제 기록으로 확인
  • T-15분 스냅샷 백업은 그대로 유지
제한 GO
샘플 UI 시연만 가능. AI·음성·자동 기억 검증 미완료 (서비스는 살아 있음)
  • 스냅샷/목업으로 시연은 계속합니다
  • 결과에 배지 표시 — 목업을 AI라고 하지 않습니다. 발표 가능 ≠ 검증 통과
  • 발표 멘트를 먼저 줄입니다. 목표 축소 > 거짓말
NO-GO
계약/서비스 자체가 깨짐 (G1~G2)
  • 수정 후 G1부터 재확인. 프론트를 붙이지 않습니다
  • 검증을 끈 채 "통과"라고 말하지 않습니다
  • 복구까지 시간이 걸리면 스냅샷으로 전환
§7과 일치: 런북 §7도 has_api_key: false·rejected를 제한 Go로, categories: [] 같은 서비스 자체 장애만 No-Go로 둡니다.
기준 버전: 커밋 8795d62 의 백엔드. 상황 개수, 429/503, CONFIG_STRICT 등은 그 버전에 실제로 있는 조건일 때만 판정 기준으로 씁니다. 확장되면 기대 계약과 일치하는지로 다시 판단하세요.
