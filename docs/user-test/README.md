# 실사용자 테스트 계획

과제 요건: 실제 사용자 **5명 이상**에게 서비스를 제공하고 피드백을 수집해 반영한다.
이 폴더: 계획(이 문서) · 진행자 체크리스트 [`facilitator-checklist.md`](facilitator-checklist.md) · 설문 [`survey.md`](survey.md) · 결과 기록 [`results.md`](results.md)

## 1. 목적과 측정할 것

| # | 질문 | 측정 | 근거 |
|---|---|---|---|
| Q1 | 처음 쓰는 사람이 여행 입력부터 오늘 학습까지 갈 수 있는가 | 과업 성공률·막힌 지점 | FR-01~07 |
| Q2 | AI 가 만든 맛집 문장이 실제로 쓸 만한가 | 문장별 '쓸 것 같다' 비율 | FR-05 |
| Q3 | **말해 보기가 실제 학습자 발화를 놓치지 않는가** | **오거부율** = 실제로 말했는데 "음성이 인식되지 않았습니다"가 나온 비율 | 두 검출기 AND 는 작은·서툰 발화를 놓칠 수 있다(`docs/research/references.md` A8·A9) |
| Q4 | 점수가 체감과 맞는가 | 맞게 말한 문장 점수, 일부러 틀린 문장 점수, 체감 일치도(5점) | FR-09, 한계: Whisper 자동 교정(C5) |
| Q5 | 피드백 문장이 도움이 되는가 | 5점 척도 + 자유 의견 | FR-09 |
| Q6 | AI 표시·동의 안내를 이해했는가 | 동의 창 내용 회상 질문 | FR-13, AI 윤리 |
| Q7 | 다시 쓰고 싶은가, 무엇을 고치면 좋은가 | 재사용 의향(5점), 자유 의견 | 개선 반영 |

## 2. 대상과 일정

- **대상**: 5명 이상. 가능하면 영어 수준이 다양하게(기초·초급·중급), 휴대폰 사용자 위주.
- **일정**: 10/19~ (팀 일정). 1인 20~25분.
- **방식**: 대면 또는 화상. 참가자 본인 휴대폰 브라우저로 https://codyssey-final.onrender.com 접속.
- **시작 10분 전**: 진행자가 `/health` 로 서버를 깨우고, 말해 보기를 한 번 해 둔다(콜드스타트 방지, `docs/score_측정_실행법.md`).

## 3. 참가자 안내·동의 (시작 전 읽어 주기)

> 오늘 테스트는 여행 영어 학습 서비스를 써 보고 의견을 듣기 위한 것입니다.
> - 일부 문장과 말하기 피드백은 **AI 가 만든 결과**이고 틀릴 수 있습니다. 장소 목록은 예시 데이터입니다.
> - 말해 보기를 쓰면, 말소리가 있을 때만 녹음이 전사 AI(Groq, AssemblyAI)로 전송되고 서버에는 저장되지 않습니다. 앱 안에서도 동의를 다시 묻습니다.
> - 진행자는 화면에서 본 것과 답변만 기록합니다. **이름·연락처는 결과 문서에 쓰지 않고 P1, P2… 로 기록**합니다.
> - 언제든 중단할 수 있습니다. 민감한 개인정보는 말하지 말아 주세요.
>
> 동의하시면 시작하겠습니다. (구두 동의 여부를 결과 표에 기록)

## 4. 과업 (참가자에게 순서대로 요청)

| # | 과업 | 성공 기준 | 관찰 포인트 |
|---|---|---|---|
| T1 | 다음 달 뉴욕 3박 여행을 입력하고 학습 일정을 만들어 보세요 | 홈 화면에서 오늘 학습이 보임 | 입력 오류, 헤맨 곳 |
| T2 | 보고서에서 가지 않을 장소 하나를 빼고 확정하세요 | 방문 순서 화면 도달 | '예시 데이터' 고지를 봤는지 |
| T3 | 오늘 학습 카드를 끝까지 뒤집고 듣기를 눌러 보세요 | 학습 완료 | 카드 뒤집기 발견 여부 |
| T4 | 맛집 문장 3개를 골라 '실제로 쓸 것 같은지' 말해 주세요 | – | 문장별 예/아니오 |
| T5 | 아무 카드에서 **말해 보기**로 문장을 **평소처럼** 말해 보세요 (3개 문장) | 점수 표시 | **오거부**(말했는데 인식 안 됨) 횟수, 점수 |
| T6 | 같은 문장 하나를 **일부러 한 단어 빼고** 말해 보세요 | 점수가 낮아지고 빠진 단어 피드백 | 체감 일치 |
| T7 | 홈에서 'AI · 개인정보' 카드를 찾아 복습 목록을 확인하세요 | 카드 도달 | 동의 내용 이해 |

## 5. 기록 규칙

- 진행자는 과업 중 **설명·도움을 최소화**하고, 도움을 줬다면 그 과업은 '도움 성공'으로 기록한다.
- T5 는 **문장마다** 결과(점수 / "음성이 인식되지 않았습니다" / 오류)를 그대로 적는다. 오거부율 = 인식 실패 횟수 ÷ 실제로 말한 횟수.
- 화면 오류·이상 동작은 시각과 함께 적고, 가능하면 개발자 도구 없이 화면 사진만 남긴다(개인정보 주의).
- 끝나면 바로 설문(`survey.md`)을 받는다.

## 6. 반영 절차

1. 결과를 `results.md` 에 모은다(참가자별 표 → 요약).
2. 문제마다 **심각도**(막힘 / 불편 / 의견)와 **빈도**(몇 명)를 매긴다.
3. 상위 문제부터 이슈·PR 로 고치고, `results.md` 의 "피드백 → 반영" 표에 PR 번호를 적는다.
4. 반영 결과를 루트 `README.md` 9장 "사용자 테스트" 에 요약한다(과제 결과 예시 형식: "피드백" → "반영 사항").
5. **오거부율이 10% 를 넘으면** VAD 판정(두 검출기 AND)을 다시 검토한다 — 근거 문헌 A8·A9.
