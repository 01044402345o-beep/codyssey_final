# 검토 루브릭 (Final Project)

문서·코드를 다른 맥락의 검토자(다른 Claude 대화/세션, 또는 팀원)에게 맡길 때 쓰는 기준이다.
회차마다 이 파일 전체를 검토자에게 주고, 결과는 `docs/review-log.md`에 남긴다.

> **원문 인용 출처**: R1~R5와 팀 인원 문구는 과제 원문(`과제원문.html`)에서 인용한 것으로 2026-10-07 검토 의견 문서(docx)가 전달했다.
> 이 저장소에는 원문 파일이 없어 이 파일 작성 시점에 직접 대조하지 못했다. 원문을 가진 사람이 한 번 대조하면 확정이다.

## 검토 규칙 (먼저 읽는다)

1. **대상 고정**: 검토자는 시작할 때 `git rev-parse HEAD` 결과를 **먼저 적는다**. 의뢰받은 대상 SHA와 다르면 **검토를 중단**하고 알린다.
   (낡은 커밋을 현재로 보고 이미 고친 문제를 다시 보고하는 사고를 막기 위한 규칙이다.)
2. **근거 표기**: 모든 지적에 `파일:줄` 또는 원문 인용을 붙인다. 근거를 못 대면 "추정"이라고 쓴다.
3. **확인 방식**
   - 코드 회차: 해당 테스트/명령을 **직접 실행**한 결과를 근거로 쓴다. 실행하지 않았으면 "미실행"이라고 쓴다.
   - 문서 회차: **과제 원문 또는 코드의 해당 줄과 대조**한다. (문서와 구현이 어긋나는 곳을 잡기 위해서다.)
4. **작성자는 지적을 수용하기 전에 직접 확인한다.** 각 지적에 [수용/부분수용/거부]와 이유를 한 줄 적는다.
5. **쓰기 담당은 한 명**이다. 검토자는 수정안을 제안만 하고 저장소에 직접 쓰지 않는다.
6. 칭찬은 쓰지 않는다. 문제가 없는 항목은 "이상 없음"만 적는다. 증거 등급은 `구현됨 → 합성·로컬 테스트 확인 → 실환경 검증 완료`를 섞어 쓰지 않는다.

## 이 저장소에서 알려진 사실 (검토자가 다시 확인할 것)

- **Long-term Memory 저장 위치**: 복습 목록은 **브라우저 `localStorage`(`cd_weak`)에만** 저장된다. 서버에는 사용자별 저장소가 없고, 요청마다 상황 ID만 실어 보낸다.
  → 기기·브라우저가 바뀌면 사라진다. 원문의 "사용자별 기록·선호도를 저장·활용" 정의에 대해 R2 판정이 약해질 수 있으니 별도 판단이 필요하다.
- **동의(R5)**: 말하기 연습은 **선택 기능이라 처음 녹음할 때 동의**를 받는다(보내는 것·받는 곳·목적·보관·브라우저 저장, Gemini 무료 등급 데이터 사용·민감정보 금지). 동의 전에는 마이크를 열지 않고, 거부해도 나머지 서비스는 그대로다(개인정보보호법 제22조: 선택 동의 거부를 이유로 서비스 제공 거부 금지 — 법률 자문 아님). 동의 기록(`cd_consent`: 버전 3·시각)을 저장하고, 홈 "AI · 개인정보" 카드에서 철회하면 동의 기록과 복습 목록을 지운다. 문장 생성 시 Gemini 로 가는 도시·장소명·상황 이름은 개인정보가 아니므로 로그인 화면·홈 카드에 고지만 한다.
- **오디오 보관**: 서버 코드(`backend/app/main.py`)는 받은 녹음을 메모리에서 Gemini로 넘기기만 하고 파일로 쓰지 않는다. **Render·Google 쪽 처리는 코드로 확인할 수 없다.**
- **Gemini 약관**: 무료 등급의 데이터 사용 조건은 이 저장소에서 확인한 적이 없다. 사용 중인 키의 등급과 현행 약관을 직접 확인해야 한다.
- 이 판단은 과제 요건 수준이며 법적 충분성을 보장하지 않는다.

검토자는 이 문서와 코드만 보고 팀원 한 명에게 던질 질문 3개를 만든다. **답이 저장소에 없으면 그 자체를 결함으로 표시한다.**
질문은 AI가 답하지 않고 사람이 직접 답한다. 답하지 못한 질문이 실제 약점이다.
