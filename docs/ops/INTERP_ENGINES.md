# 실시간 통역 엔진 켜기·순서 정하기 — 관리자 안내

코드를 몰라도 이 문서만 보고 설정할 수 있게 썼다. 모든 설정은 **Render 대시보드의 환경 변수**로 한다.
코드를 고치거나 다시 올릴 필요는 없다(동의 문구를 바꿔야 하는 경우만 예외 — 5절).

## 1. 먼저 알아 둘 것

- **엔진** = 실제로 말을 알아듣고 번역하는 외부 회사 서비스다. 앱은 소리를 그 회사로 보내고 자막을 받아 보여 준다.
- 쓸 수 있는 엔진은 6개다.

  | 엔진 이름(설정에 쓰는 값) | 회사 | 특징 | 비용(공개 단가 기준) |
  |---|---|---|---|
  | `soniox` | Soniox (미국) | 한 번에 한국어↔영어 양쪽. 자막만 나온다 | 가장 쌈(시간당 약 $0.12 + 번역 글자 요금 확인 필요) |
  | `openai` | OpenAI (미국) | 번역 음성까지 나온다. 한 방향. **한국어로 번역해 내보내는지는 문서에서 확인되지 않음** | 분당 $0.034(시간당 약 $2) |
  | `gemini` | Google (미국 등) | 번역 음성까지 나온다. 한 방향. 미리보기(preview) 모델 | 키의 요금제(무료/유료)에 따라 다름 |
  | `deepl` | DeepL (독일) | 자막만. **아직 실제로 확인되지 않음** | 영업 문의 |
  | `azure` | Microsoft (미국 등) | 한국어·영어 자동 감지. 자막만 | 시간당 약 $2.5(대상 언어 2개, 조사 문서의 목록가 예시) |
  | `fake` | — | 시험용. 번역하지 않고 정해진 문장만 보낸다 | 없음 |

- 엔진이 **켜지려면 세 가지가 모두** 맞아야 한다.
  1. **켜기 목록**(`INTERP_PROVIDERS`)에 그 엔진 이름이 있다.
  2. 그 엔진의 **키**가 들어 있다(아래 3절 표).
  3. (엔진에 따라) 추가 조건을 갖췄다(아래 3절 표).

  키만 넣어서는 켜지지 않는다. 일부러 이렇게 만들었다 — 예를 들어 Gemini 키는 앱의 문장 만들기에도 쓰이는 키라서, 키가 있다는 이유만으로 통역이 켜지면 사용자 음성이 의도치 않게 Google 로 간다.

## 2. 설정하는 곳 (Render 대시보드)

1. Render 에 로그인 → 백엔드 서비스를 연다(주소가 `codyssey-final.onrender.com` 인 서비스. 설정 파일 `render.yaml` 에는 `codyssey-api` 라는 이름으로 적혀 있다).
2. 왼쪽 메뉴 **Environment** 를 연다.
3. **Add Environment Variable** 로 이름(Key)과 값(Value)을 넣는다. 이미 있으면 값을 고친다.
4. **Save Changes** 를 누른다. 서버가 자동으로 다시 시작된다(보통 몇 분).
5. 다시 시작이 끝나면 6절의 방법으로 결과를 확인한다.

## 3. 엔진별 조건

| 엔진 | 넣어야 하는 키 | 추가 조건 |
|---|---|---|
| `soniox` | `SONIOX_API_KEY` | 없음 |
| `openai` | `OPENAI_API_KEY` | 없음. **주의:** 이 키는 말하기 연습의 받아쓰기에도 쓰여서 이미 들어 있다. 켜기 목록에 `openai` 가 있으면 바로 켜진다 |
| `gemini` | `GEMINI_API_KEY` | **유료 요금제 키**여야 한다(무료 키는 보낸 음성이 Google 의 제품 개선에 쓰일 수 있다). 이 키는 앱의 문장 만들기와 같은 키다 |
| `deepl` | `DEEPL_API_KEY` | 실제 호출로 확인되지 않았다. 켜기 전에 개발자에게 시험을 요청한다 |
| `azure` | `AZURE_SPEECH_KEY` **와** `AZURE_SPEECH_REGION`(예: `koreacentral`) | 서버에서 Azure 프로그램을 불러올 수 있어야 한다 — 6절의 `azure_speech_sdk` 가 `true` 인지 확인 |
| `fake` | 없음 | `INTERP_ALLOW_FAKE` 를 `1` 로 넣어야 한다. **운영에서는 쓰지 않는다**(자동 시험용) |

## 4. 켜기와 순서 — 설정 값 세 가지

### 4-1. `INTERP_PROVIDERS` — 켤 엔진과 **우선순위**

- 값: 엔진 이름을 **쉼표로 나열**한다. 띄어쓰기·대소문자는 상관없다.
- **앞에 쓴 엔진이 먼저 쓰인다.** 사용자가 따로 고르지 않으면 목록에서 "켜져 있고 키가 있는" 첫 엔진을 쓴다.
- 비워 두거나 아예 넣지 않으면 기본값 `soniox,openai,fake` 가 쓰인다.
- 앱 화면에도 이 순서대로 엔진 단추가 나오고, 첫 엔진이 기본으로 선택돼 보인다.

### 4-2. `INTERP_PROVIDER` — **한 엔진으로 고정** (끝에 S 가 없다)

- 값: 엔진 이름 하나. 넣으면 **그 엔진만** 쓴다. 사용자가 고른 엔진도 무시하고, 화면에 엔진 고르는 단추가 나오지 않는다.
- 그 엔진이 켜기 목록에 없거나 키가 없으면 통역이 **아예 안 된다**("지금은 쓸 수 없어요"). 고정할 때는 4-1 목록에도 같은 이름이 있는지 확인한다.
- 고정을 풀려면 이 변수를 **지운다**.

### 4-3. 사용자의 선택

- 엔진이 두 개 이상 켜져 있으면 사용자가 통역 화면에서 엔진을 고를 수 있고, 그 선택은 사용자의 브라우저에 기억된다.
- 사용자가 고른 엔진이 나중에 꺼지면 자동으로 우선순위 첫 엔진을 쓴다.
- 사용자 선택까지 막고 싶으면 4-2(고정)를 쓰거나, 켜기 목록에 엔진을 하나만 둔다.

### 결정 순서 (한눈에)

```
INTERP_PROVIDER(고정)가 있나? ── 예 → 그 엔진(쓸 수 없으면 통역 불가)
        │ 아니오
사용자가 고른 엔진이 켜져 있고 키가 있나? ── 예 → 그 엔진
        │ 아니오
INTERP_PROVIDERS 에 적힌 순서대로, 켜져 있고 키가 있는 첫 엔진
        │ 하나도 없으면
"지금은 실시간 통역을 쓸 수 없어요"
```

## 5. 자주 쓰는 설정 예

| 하고 싶은 것 | `INTERP_PROVIDERS` | `INTERP_PROVIDER` |
|---|---|---|
| 지금처럼(기본) | (넣지 않음) → `soniox,openai,fake` | (넣지 않음) |
| **OpenAI 보다 Gemini 를 먼저** | `soniox,gemini,openai` — Soniox 다음 Gemini. Soniox 보다도 먼저 쓰려면 `gemini,soniox,openai` | (넣지 않음) |
| Gemini 만, 사용자 선택 없이 | `gemini` | 또는 `gemini` 로 고정 |
| 비싼 OpenAI 를 끄고 Soniox 만 | `soniox` | (넣지 않음) |
| Azure 를 예비로 추가 | `soniox,azure` | (넣지 않음) |
| 통역을 잠시 전부 끄기 | `none` 처럼 **없는 이름 하나** | (넣지 않음) |

> "OpenAI 보다 Gemini 우선" 예: Render → Environment → `INTERP_PROVIDERS` = `soniox,gemini,openai` → Save Changes.
> 이렇게 하면 사용자가 엔진을 고르지 않았을 때 Soniox 를, Soniox 키가 없으면 Gemini 를, Gemini 키도 없으면 OpenAI 를 쓴다. 화면의 엔진 단추도 Soniox·Gemini·OpenAI 순서로 나온다.
> 단, **이전에 OpenAI 를 직접 고른 사용자**는 계속 OpenAI 를 쓴다(4-3). 모두를 Gemini 로 보내려면 `INTERP_PROVIDER` = `gemini` 로 고정한다.

### 새 엔진을 켜기 **전에** 해야 하는 일 (중요)

`gemini`·`deepl`·`azure` 처럼 **지금 개인정보 처리방침에 없는 회사**를 켜면, 사용자 음성이 처리방침에 적히지 않은 곳으로 간다. 켜기 전에:

1. 개발자에게 **처리방침(3절 표)에 그 회사 행 추가**를 요청한다.
2. 개발자에게 **동의 창 '받는 곳' 문구 수정과 면책 버전 올리기**를 요청한다 — 그래야 기존 사용자도 새 회사에 대해 다시 동의한다. (이 두 가지는 코드 수정이 필요하다.)
3. 반영되어 배포된 뒤에 켜기 목록에 넣는다.

현재 처리방침에 적힌 통역 회사: **Soniox, OpenAI**.

## 6. 설정이 먹혔는지 확인

브라우저 주소창에 아래 주소를 열면 글자(JSON)가 보인다. 로그인 없이 열 수 있고, 키 값은 나오지 않는다.

- **`https://codyssey-final.onrender.com/interp/providers`**
  - 엔진마다 `"available": true` 면 지금 쓸 수 있다.
  - `"priority": 1, 2, …` 이 우선순위다(켜지지 않은 엔진은 `null`). 위에서부터 이 순서로 나온다.
- **`https://codyssey-final.onrender.com/health`**
  - `"azure_speech_sdk": true` 여야 Azure 를 켤 수 있다.

## 7. 다른 제한(필요할 때만)

| 변수 | 뜻 | 기본 |
|---|---|---|
| `INTERP_MAX_SECONDS` | 한 번 통역할 수 있는 최대 시간(초) | `180` |
| `INTERP_STARTS` / `INTERP_WINDOW` | 한 계정·한 IP 가 `INTERP_WINDOW` 초 동안 통역을 시작할 수 있는 횟수 | `6` 번 / `600` 초 |
| `GEMINI_LIVE_MODEL` | Gemini 통역 모델 이름(구글이 이름을 바꿨을 때만) | `gemini-3.5-live-translate-preview` |
| `AZURE_SPEECH_ENDPOINT` | Azure 접속 주소를 직접 지정(보통 필요 없음) | 지역으로 자동 |

- 실시간 통역은 **로그인한 계정만** 쓸 수 있다(로그인 없이 시작한 사용자는 불가). 이 규칙은 설정으로 끌 수 없다.

## 8. 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 화면에 "지금은 쓸 수 있는 통역 엔진이 없어요" | 6절에서 `available` 이 모두 `false` 인지 → 켜기 목록 이름 철자, 키 유무 |
| 고정(`INTERP_PROVIDER`)했더니 통역이 안 됨 | 같은 이름이 `INTERP_PROVIDERS` 에도 있는지, 그 엔진 키가 있는지 |
| Azure 가 `available: false` | `AZURE_SPEECH_REGION` 을 넣었는지, `/health` 의 `azure_speech_sdk` 가 `true` 인지 |
| "통역 서비스에 연결하지 못했어요" | 키가 틀렸거나 만료됐거나, 그 회사 장애. 다른 엔진을 켜기 목록 앞으로 옮겨 우회 |
| 순서를 바꿨는데 어떤 사용자는 예전 엔진을 씀 | 그 사용자가 직접 고른 것(4-3). 모두 바꾸려면 고정(4-2) |
