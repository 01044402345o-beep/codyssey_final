### 2.2 새 동의 창 — 문구 초안

**기존 말하기 동의와 별개의 동의**로 둡니다. 키 예시는 `consent.live` (6장 Q3). 실시간 회화를 처음 시작할 때만 띄우고, **동의 전에는 마이크도 열지 않습니다**. 현재 `toggleSpeak`의 원칙을 그대로 따릅니다.

> **제목:** 실시간 AI 회화 연습 전에 확인해 주세요
>
> **상대는 AI예요** · 입국심사관·직원 역할은 사람이 아니라 AI가 해요. AI가 말하는 입국·세관 규정은 틀릴 수 있어요. 실제 여행 전에는 대사관이나 공식 누리집에서 꼭 확인하세요.
>
> **보내는 것** · 연습하는 동안 마이크에 들어온 내 목소리(실시간), 고른 상황(예: 입국심사), 화면의 연습 정보
>
> **받는 곳 (국외 이전)** · Google LLC의 Gemini API · 미국 등 Google이 시설을 둔 국가 · 대화하는 동안 실시간으로 · 암호화된 연결로 보내요. 내 목소리는 이 서비스 서버를 거치지 않고 Google로 바로 가요. *(서버 중계 방식이면 이 문장 대신 "이 서비스 서버({host})를 거쳐 Google로 가요"라고 씁니다)* · 연락처: Google 개인정보 문의 창구 *(처리방침에 정확한 주소를 기재)*
>
> **목적** · AI와 영어로 역할극 대화를 하고, 끝난 뒤 피드백을 받기 위해서만 써요
>
> **보관** · 이 서비스: 녹음은 **저장하지 않아요**. 대화 자막(글)은 *[이 기기에만 / 로그인하면 내 계정에]* 최대 30일 보관하고, 직접 지우거나 탈퇴하면 바로 지워요. · Google: 유료 API 약관에 따라 **AI 학습에 쓰지 않아요**. 다만 정책 위반 감지와 법적 의무를 위해 일정 기간 기록할 수 있어요(Google은 그 기간을 공개하지 않아요).
>
> **꼭 지켜 주세요** · 여권번호, 카드번호, 집 주소, 건강 정보 같은 실제 개인정보는 말하지 마세요. 필요한 정보는 화면의 **연습용 가짜 정보**를 읽으면 돼요.
>
> **이용 시간** · 하루 최대 {N}분, 한 번에 최대 {M}분이에요.
>
> **거부할 수 있어요** · 동의하지 않아도 카드 학습, 듣기, 한 문장씩 채점하는 '말해보기'는 그대로 쓸 수 있어요. 동의는 홈 'AI · 개인정보'에서 언제든 철회할 수 있어요. 철회하면 저장된 대화 자막도 함께 지워져요.
>
> ☐ **(필수)** 만 18세 이상이에요.
> ☐ **(필수)** 위 내용대로 내 목소리가 미국 등 국외의 Google로 전송되는 것(국외 이전)에 동의해요.
>
> [동의하지 않기] [동의하고 시작하기] ← 두 체크박스를 모두 고르기 전에는 비활성

설계 메모:
- 국외 이전 동의는 **다른 동의와 묶지 않고 별도 체크박스**로 받습니다(제28조의8 ①1 "별도의 동의"). 미리 체크해 두지 않습니다.
- 18세 미만이라고 답하면 "실시간 회화는 만 18세 이상만 쓸 수 있어요. 카드 학습과 말해보기는 계속 쓸 수 있어요."라고 안내하고 기능을 끕니다. 나이는 저장하지 않고 '18세 이상 확인함 + 시각'만 저장합니다.
- 50~60대 사용자를 생각해 **요약을 먼저 3줄**("AI와 대화해요 / 목소리가 미국 Google로 가요 / 녹음은 저장 안 해요")로 보여 주고, "자세히 보기"를 펼치면 위 전문이 나오게 하는 2단 구성을 권합니다. 글자 크기는 본문보다 크게 합니다.

### 2.3 버튼 아래·로그인·홈 고지 문구 초안

- **회화 시작 버튼 아래 한 줄** (`speakHtml`의 `speak-note`와 같은 자리):
  > 대화 중 내 목소리는 Google Gemini(미국)로 바로 전송돼요 · 녹음은 저장하지 않아요 · 상대는 AI예요(규정 안내는 틀릴 수 있어요) · 오늘 남은 시간 {n}분
- **대화 화면 상단 상시 배지**: `AI 역할극 · 실제 심사관 아님` · `● 마이크 켜짐` (마이크가 켜져 있을 때만 빨간 점)
- **로그인 화면 `scrLogin` 문장 추가**:
  > 실시간 AI 회화를 쓰면 동의한 뒤에만 목소리가 Google Gemini(미국)로 실시간 전송되고, 녹음은 저장하지 않아요.
- **홈 'AI · 개인정보' 카드에 추가할 줄**:
  > · 실시간 AI 회화 동의: **동의함 (날짜)** / 동의하지 않음 · 오늘 사용 {n}/{N}분
  > · 대화 자막: **{k}개** · {이 계정에 / 이 브라우저에만} 저장돼요 (30일 뒤 자동 삭제) [대화 자막 삭제]

### 2.4 저장하는 것과 저장하지 않는 것

| 데이터 | 저장 여부 | 위치·기간 | 이유 |
|---|---|---|---|
| 원본 음성(사용자·AI) | **저장하지 않음** | 메모리에서 바로 흘려보냄. 서버 중계 방식이어도 디스크에 쓰지 않음 | 가장 민감하고 학습 목적에 꼭 필요하지 않습니다. 현재 원칙("녹음 파일은 올리지 않아요")과도 같습니다 |
| 다시 듣기용 내 녹음 | 선택 사항 | **브라우저 메모리에만**, 화면을 떠나면 버림 (현재 `SPK.clip`과 같음) | 기존 방식을 유지합니다 |
| 대화 자막(양쪽 전사) | 저장 가능 (기본값 제안: 저장) | 비로그인: 브라우저. 로그인: Firestore `users/{uid}` **문서 안 필드**(하위 컬렉션 아님). **30일** 뒤 자동 삭제, 세션 수 상한(예: 최근 20개) | 복습과 피드백에 필요합니다. **하위 컬렉션에 두면 현재 `delete_document`가 지우지 못합니다.** 하위 컬렉션을 꼭 써야 하면 `erase()`에 하위 컬렉션 삭제 단계를 추가하고 ledger에 기록해야 합니다. 문서 크기 한도(1MiB)를 넘지 않게 상한을 둡니다 |
| 세션 메타데이터 | 저장 | uid, 시작 시각, 분, 턴 수, 상황 id, 종료 사유, 토큰 사용량 합계. **내용은 넣지 않음** | 비용 상한, 일일 한도, 남용 탐지에 필요합니다. 탈퇴 시 함께 지웁니다 |
| 일일 사용량 카운터 | 저장 | `usage/{uid}/{YYYY-MM-DD}` 또는 `users/{uid}` 필드. 7일 뒤 삭제 | 한도 검사에 필요합니다. 별도 경로에 두면 탈퇴 시 삭제 단계가 따로 필요합니다 |
| 서버 로그 | 메타만 | 상태 코드, 분, 오류 코드 | **전사 내용과 사용자 발화를 로그에 남기지 않습니다.** `evidence.recent_logs`가 탈퇴 실패 시 최근 로그를 봉인하고 GitHub 등에 보관하기 때문입니다. `scrub_text`는 자격증명만 가리고 대화 내용은 가리지 않습니다 |
| Google 쪽 | 우리가 제어할 수 없음 | 유료 약관: 학습 안 함, 제한 기간 기록. AI Studio 로그 기능은 **켜지 않음** | 고지에 반영합니다 |

**탈퇴 연동** (`/account/erase` → `firebase_admin.erase`):
1. 자막을 `users/{uid}` 문서 필드에 두면 **기존 탈퇴 경로 그대로** 지워집니다. 가장 단순한 방법입니다.
2. 사용량 카운터나 세션 메타를 다른 경로에 두면 `erase()` 순서에 "사용량 문서 삭제" 단계를 추가하고 `ledger`에 남깁니다. 실패하면 기존처럼 흔적을 되돌리고 증거를 봉인합니다.
3. **동의 철회** 때도(현재 철회하면 복습 목록을 지우는 것처럼) 실시간 동의와 대화 자막을 함께 지웁니다.
4. 진행 중인 세션은 탈퇴·철회 즉시 끊고, 이미 발급한 임시 토큰은 짧은 만료로 자연히 무효가 되게 합니다(`newSessionExpireTime` 1분).

- OpenAI는 사용자 오디오가 100ms당 1토큰, AI 오디오가 50ms당 1토큰입니다(https://developers.openai.com/api/docs/guides/realtime-costs **[확인]**).

**중요 — 턴마다 누적 컨텍스트가 다시 과금됩니다.**
- Gemini Live는 각 턴에서 시스템 지시문과 지난 대화 전체를 입력 토큰으로 다시 과금하며, 그 양은 `usage_metadata`로 확인할 수 있습니다. Google Cloud 「Live API best practices」 **[2차 검색 요약, 원문 재확인 권장]** (https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/live-api/best-practices)
- Google 포럼 직원 답변에 따르면 `gemini-3.8-live`는 컨텍스트 캐싱을 지원하지 않습니다 **[2차]** (https://discuss.ai.google.dev/t/does-gemini-live-native-audio-bill-cumulative-prompt-tokens-on-every-turn-cost-seems-to-scale-with-turn-count-not-call-duration/173248).
- 따라서 비용은 **세션 길이보다 턴 수에 비례해 늘어납니다**.
- OpenAI도 턴마다 대화 전체를 다시 보내지만 캐시 단가가 적용될 수 있습니다.

### 3.2 5분 역할극 1회 비용 **[추정]**

## 4. 보안·남용 대응

### 4.1 키 노출 — 임시 토큰 방식

현재 `GEMINI_API_KEY`는 서버에만 있습니다. 실시간 회화에서는 두 가지 방식이 있습니다.

| 방식 | 장점 | 단점 |
|---|---|---|
| **A. 임시 토큰으로 브라우저가 Google에 바로 연결** (권장) | 지연이 가장 짧습니다. Render가 WebSocket을 오래 붙잡지 않습니다. 음성이 우리 서버를 거치지 않습니다(보관 위험 낮음) | 서버 VAD가 빠지고, 상한은 토큰 만료와 클라이언트 보고에 의존합니다. 사용량은 클라이언트가 보내는 `usage_metadata`나 GCP 청구로만 볼 수 있습니다 |
| B. 서버 중계(WebSocket relay) | 상한을 서버에서 강제하고 사용량을 정확히 집계합니다 | Render 지연이 늘고 인스턴스 부하가 커집니다. 음성이 서버 메모리를 지나갑니다 |

A 방식의 발급 API 설계(예: `POST /live/token`):
1. **Firebase ID 토큰 필수**: 기존 `/auth/me`, `/user/state`와 같은 검증을 씁니다. `/speak-check`처럼 토큰 없이 열어 두지 않습니다. 탈퇴 흔적(`is_erased`)도 확인합니다.
2. 서버에서 `users/{uid}`의 실시간 동의와 18세 확인 기록을 확인합니다.
3. 일일 분량과 전역 예산을 트랜잭션으로 확인합니다.
4. 토큰 설정:
   - `uses: 1`
   - `newSessionExpireTime` 60초
   - `expireTime` 6분
   - `liveConnectConstraints`로 **모델·시스템 지시문·응답 형식·자막 설정을 서버에서 잠급니다**. 클라이언트가 시스템 지시문을 바꿀 수 없게 하기 위함이며, 잠금 범위는 실제로 시험해 봐야 합니다 **[미확인]**.
   - 도구(function calling)는 **넣지 않습니다**.
5. 발급 속도 제한: uid당 시간당 6회, IP당 분당 N회. 현재 `rate_limit`은 IP 기준이고 프로세스 메모리에 있습니다. 런북에 따르면 `TRUSTED_PROXY_HOPS=0`이면 모두 한 IP로 묶이므로 **uid 기준이 주 방어선**이어야 합니다.
6. `ALLOW_ORIGINS`(기본 `*`)를 프론트 주소로 좁힙니다. 런북 F11 설명처럼 이것만으로 직접 호출을 막지는 못합니다. 선택 사항으로 Firebase App Check를 붙이는 방법도 있습니다.
7. 토큰 값과 API 키는 로그에 남기지 않습니다(팀 규칙. `evidence.scrub_text`가 있어도 처음부터 쓰지 않는 것이 원칙입니다).

### 4.2 음성 프롬프트 인젝션과 주제 이탈

위험: 사용자가 말로 "Ignore your instructions…"라고 하거나, 역할극과 무관한 질문(숙제, 정치, 성인 콘텐츠)으로 끌고 가는 경우입니다. 그 밖에 시스템 지시문 노출 요청, AI를 무료 범용 음성 비서로 쓰는 경우(비용 유출)도 있습니다. OWASP는 이를 LLM01 Prompt Injection으로 분류합니다(OWASP GenAI Top 10 2025, https://genai.owasp.org/llmrisk/llm01-prompt-injection/).

완화:
- **피해 반경 최소화**: 도구, 검색, 외부 링크, 개인정보 접근이 없으면 인젝션이 성공해도 피해는 '말'에 그칩니다. 시스템 지시문에 비밀(키, 내부 URL)을 넣지 않습니다.
- **시스템 지시문 범위 고정**: 상황 화이트리스트(입국심사, 세관, 호텔 체크인, 식당 등)를 둡니다. 범위 밖 요청에는 역할을 유지한 채 "Let's get back to your arrival card."처럼 되돌립니다. 3번 이탈하면 세션을 종료하고 안내합니다.
- **이용 시간 상한 자체가 남용 방어입니다**(4.1, 3.4).
- **사후 점검**: 세션이 끝나면 출력 자막에 가벼운 분류(키워드 또는 저비용 텍스트 모델)를 적용해 이탈·유해 비율을 집계합니다(내용은 저장하지 않고 플래그만 저장). 이상 uid는 한도를 낮춥니다.
- **안전 설정**: Gemini Live에서 안전 필터 설정 범위는 **[미확인]**입니다. 출시 전 확인해야 합니다.

### 4.3 유해 콘텐츠·사칭

- **사칭 방지**:
  - AI는 실제 기관명을 사칭하지 않습니다. "U.S. CBP officer"가 아니라 "practice immigration officer"로 부르게 합니다.
  - 시작 인사에 "I'm an AI practice partner."를 넣습니다.
  - 화면에 상시 배지를 둡니다(1장 #7 AI 기본법 투명성).
- **실제 개인정보 요구 금지**: 역할극에서 여권번호나 숙소 주소를 물을 때는 **화면의 가짜 정보 카드**(예: Passport M12345678, Hilton Midtown)를 읽게 합니다. 시스템 지시문에 "실제 정보를 요구하지 말 것"을 넣습니다. 사용자가 실제 정보를 말할 위험을 줄이기 위해서입니다.
- **목소리 복제 금지**: 사용자 목소리를 학습하거나 복제하는 기능을 넣지 않습니다(민감정보가 되고 딥페이크 위험이 있음).
- **신고 버튼**: "이상한 응답 신고"를 누르면 해당 턴의 자막 일부만 **사용자 동의를 받아** 전송합니다.

### 4.4 정확성 위험 — 잘못된 입국·세관 규정

위험: AI가 "면세 한도는 $X", "ESTA 없이 입국 가능" 같은 **틀린 사실을 확신 있게** 말하면, 50~60대 초보 여행자가 그대로 믿을 수 있습니다.

완화:
- 역할극은 **질문과 응답 연습**에 집중시킵니다. 시스템 지시문에 "구체적 수치, 비자·면세·검역 규정을 단정하지 말 것. 질문받으면 'Please check the official website before your trip'으로 답할 것"을 넣습니다.
- 그라운딩(검색)은 쓰지 않습니다(30일 저장, 비용, 오답 가능성).
- 규정 정보가 필요하면 **팀이 공식 출처로 검수한 사실 카드**(출처 URL과 확인 날짜 표시)를 화면에 따로 보여 주고, AI 발화와 구분합니다.
- 피드백 단계에서도 규정에 대한 언급을 금지하고, 표현 교정만 하게 합니다.
- 동의 창, 대화 화면, 결과 화면 세 곳에 "규정은 공식 출처에서 확인"을 표시합니다.

### 4.5 기타

- 마이크 상태를 항상 표시하고, 세션이 끝나면 `getUserMedia` 트랙을 즉시 정지합니다(현재 `stopTracks` 패턴 재사용).
- 탭을 숨기거나(`visibilitychange`) 화면을 벗어나면 세션을 자동 종료합니다. 백그라운드 과금과 사용자가 모르는 녹음을 막기 위해서입니다.

### 4.6 접근성·포용성 (50~60대, 청각장애)

- **양쪽 실시간 자막**: Live API의 입력·출력 오디오 전사 설정을 켜서 AI와 내 말을 모두 글로 보여 줍니다(설정 이름과 지원 모델은 **[미확인]**, 시험 필요). 글자 크기를 조절할 수 있게 하고 고대비를 지원합니다.
- **텍스트로 답하기**: 청각·발화가 어려운 사용자를 위해 마이크 대신 키보드 입력을 허용합니다(Live API는 텍스트 입력도 받음).
- **누르고 말하기 기본**: 열린 마이크는 언제 말해야 할지 몰라 불안하고, 비용도 늡니다. 버튼을 누르는 동안만 녹음하는 방식을 기본으로 합니다.
- **천천히 / 다시 / 한국어 힌트 버튼**: "Could you say that again more slowly?"를 버튼 하나로 보냅니다. 말이 끝났다고 판단하는 침묵 시간을 길게 설정합니다(설정 가능 여부 **[미확인]**).
- **시각적 차례 표시**: "AI가 말하는 중 / 내 차례" 표시와 진동(모바일)을 둡니다.
- **대화 후 전체 자막과 교정본**을 제공해 다시 읽을 수 있게 합니다.
- 50~60대 사용성 테스트(`docs/user-test/`)에 실시간 시나리오를 추가합니다.

- [ ] 턴별 `usage_metadata`를 **모두 합산**해 1회 비용 추정. 마지막 스냅샷만 쓰면 과소 추정됩니다(포럼 보고 **[2차]**)
- [ ] GCP 청구액과 우리 추정치의 일별 비교(차이가 20% 넘으면 경보)
- [ ] 토큰 발급 성공·거절(동의 없음, 한도 초과, 예산 초과, 킬 스위치) 건수
- [ ] Live 연결 오류 코드(1008/1011 끊김, GoAway), 첫 음성까지 지연
- [ ] 턴 방식 대체 비율
- [ ] 이탈·유해 플래그 비율, 신고 건수
- [ ] `/health`에 `live_enabled`, `live_budget_used_pct` 추가(값만, 키는 노출하지 않음). 런북 T-30분 점검 항목에 포함

### 5.2 킬 스위치와 단계적 출시

- [ ] 환경변수 스위치(제안: `VOICE_AGENT_ENABLED`, `VOICE_DAILY_MINUTES_CAP`, `VOICE_USER_DAILY_MINUTES`, `VOICE_SESSION_MAX_SEC`. **현재 존재하지 않는 이름**)
- [ ] 끄면 1분 안에 새 세션 발급이 0이 되는지 시험. 진행 중 세션은 최대 `expireTime`(6분)까지 이어질 수 있음을 런북에 적기
- [ ] 출시 순서: 팀 내부 → 허용 목록 uid(테스터) → 전체의 10% → 전체
- [ ] 실시간 전용 Gemini 키·프로젝트를 분리하고, 폐기 절차를 런북 F11에 추가

### 5.3 사고 대응

| 사고 | 즉시 조치 | 후속 |
|---|---|---|

## 6. 미해결 질문

### 법률 자문에게 물을 것
1. Gemini 유료 API로 음성을 보내는 것이 제28조의8의 **처리위탁**(처리방침 공개로 갈음 가능)인가, **제3자 제공**(별도 동의 필요)인가? 이 문서는 안전하게 **별도 동의 + 처리방침 공개를 함께** 하자고 권했습니다.
2. 현재 '말해보기' 기능도 Groq·AssemblyAI·OpenAI(모두 미국)로 음성을 보내는데 국외 이전 고지가 없습니다. **기존 기능에도 보완이 필요한가?**
3. 실시간 대화 음성이 화자 식별 목적이 아니므로 **민감정보(생체인식정보)에 해당하지 않는다**는 해석이 맞는가? 서버 VAD에 pyannote를 쓰는 것이 영향을 주는가?
4. Google 유료 약관의 "제한된 기간" 기록처럼 **기간을 모를 때** 보유기간 고지는 어떻게 써야 하는가?
5. AI 기본법 제31조 의무가 우리(학습 앱)에 적용되는가? 계도기간은 언제 끝나는가?
6. 유출 통지 기한과 신고 기준(제34조, 시행령)은 무엇인가?

### 팀과 정할 것
7. **처리방침 문서를 만들 것인가?** 현재 찾지 못했습니다. 국외 수탁자, 보유기간, 이전 사항을 공개할 곳이 필요합니다.
8. 실시간 동의를 기존 `CONSENT_VERSION`을 올려서 받을 것인가, **별도 키(`consent.live`)로 분리**할 것인가? 분리하면 기존 말하기 동의자에게 다시 묻지 않아도 됩니다.
9. 임시 토큰 직접 연결(A)과 서버 중계(B) 중 무엇을 쓸 것인가? 지연과 상한 강제력의 상충 관계입니다.
10. 대화 자막을 저장할 것인가? 저장한다면 30일, 20세션이 적당한가? 비로그인 사용자도 브라우저에 저장할 것인가?
11. 연령 확인을 자기 신고로 할 것인가? Gemini 약관은 "18세 미만이 쓸 가능성이 큰 앱"도 금지하므로 마케팅 대상(50~60대)을 명확히 해 둘 필요가 있습니다.
12. 일일 한도(10분), 세션 길이(5분), 전역 예산(하루 1,000분)과 월 예산 상한은 어떻게 할 것인가?
13. Gemini 무료 등급을 지금 텍스트 피드백에 쓰고 있다면(동의 문구로 보아 그럴 가능성이 있음), 실시간 도입과 함께 **전부 유료 프로젝트로 옮길 것인가?**

### 기술적으로 확인할 것
14. Live API에서 침묵 구간이 과금되는지, 입력·출력 전사 설정, 안전 필터, `liveConnectConstraints`로 잠글 수 있는 범위를 시제품으로 실측합니다.
15. 실제 5분 세션 10회의 `usage_metadata` 합계로 3.2절 추정을 다시 계산합니다.
16. Google 공식 「Live API best practices」 원문에서 턴별 누적 과금 문구를 다시 확인합니다(이 문서에는 검색 요약으로 인용했습니다).
17. PIPC 「생성형 AI 개발·활용을 위한 개인정보 처리 안내서」(2025.8) 원문 PDF와 「생체정보 보호 가이드라인」 원문에서 음성 관련 기준을 확인합니다.
