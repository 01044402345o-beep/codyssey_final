## 1. 한 줄 결론

> **대표 집단은 40~50대 영어 초급 자유여행 준비자다.** 이 집단을 위해 **상대가 먼저, 천천히, 자막과 함께 영어로 묻고, 막히면 한국어로 한 단계씩 돕고, 점수는 대화가 끝난 뒤에** 보여 주는 롤플레이를 만든다.
> 기술은 **턴 단위(C)로 먼저 내고, 실시간 스트리밍(A, Gemini Live + 임시 토큰)은 나중에 붙인다.** 시작 장면은 **입국심사**, 그다음은 **교통**이다.
> 다만 실시간 기능과 별개로, **지금 서비스에도 개인정보 고지와 약관 문제가 있다**(5절). 먼저 정리해야 한다.

## 2. 누구를 기준으로 만드는가 — 대표 집단 ([01](01-population.md))

- **모집단:** 패키지 없이 해외여행을 직접 다니는 한국 성인 가운데 영어가 기초~초급인 사람. 영어를 공통어로 쓰는 일본·동남아도 포함한다.
  - 국민 출국자는 연 약 2,900만 명이고, 개별여행이 57%다 **[2차]**.
  - 출국자 연령은 30대 21.8%, 40대 18.7%, 50대 16.7%, 60세 이상 16.0%다 **[2차]**.
  - 60대는 패키지 비중이 63.3%라 **[2차]**, 자유여행 모집단의 중심은 30~50대다.
  - 한국 성인의 영어는 말하기(489)와 듣기(518)가 가장 약하다 **[확인, EF EPI 2025]**. 실시간 회화가 요구하는 바로 그 두 능력이다.
- **우리 표본(P1~P6, 설문 S1~S11)의 치우침:**
  - 50세 이상이 7/11로 모집단의 약 두 배다. 모집단에서 가장 많은 **30대는 0명**이다.
  - P와 S는 같은 사람이 모집했고 설문은 익명이라 겹칠 수 있다. 서로 다른 실사용자는 6~11명 범위로만 말할 수 있다.
- **대표 집단:** S6·S10·S3·S5와, 영어 초급임을 밝힌 P6. 모집단 중심과 겹치는 연령대가 40~50대뿐이고, "상대 질문도 영어로"를 직접 요청한 두 사람(P6·S6)이 이 집단에 있다.
  - 60대 이상(S7·S11)은 **접근성 하한선**(글자·버튼·청력)으로 쓴다.
  - 30대·20대·iOS 사용자는 **과소표집**이다. 2차 테스트에서 먼저 모집한다.
- **페르소나:** 50대 초반, 일본·동남아 자유여행을 준비한다. Android 폰으로 카톡 링크를 열고, 스스로 "영어까막눈"이라고 말한다. 3~5초 멈추면 고장인 줄 알고 앱을 닫는다(P2).

## 3. 무엇을 만들어야 하나 — 핵심 요구 ([01](01-population.md) §4, [03](03-conversation-design.md) §2)

**Must (첫 출시)**

| 요구 | 내용 | 근거 |
|---|---|---|
| 상대가 먼저 영어로 | 심사관·점원 역이 먼저 묻는다. 소리와 영어 자막을 함께 보여 준다. 질문은 검수된 `talk.ask` 에서 시작한다 | P6, S6 (설문 7-2) |
| 단계별 한국어 힌트 | 질문의 한국어 뜻 → 답의 첫 단어 → 예시 답 전체 순으로, 사용자가 누를 때만 하나씩 연다 | P6, `replies`·`next` |
| 느린 기본 속도, 다시 말하기 | 속도는 0.6/0.8/1.0 중 고른다. "Sorry?"를 처음 들으면 같은 문장을 더 천천히, 두 번째는 검수된 쉬운 말로 바꿔 말한다 | P3, [03] §2-3 |
| 대화 중 점수 숨김 | 대화 중에는 맞는 말을 자연스럽게 되받기만 한다("Sightseeing? Okay."). 점수와 고칠 점은 끝난 뒤 **한 가지만** 보여 준다 | S10 Q13=2, 기대 4.6 → 체감 3.6, Li et al. 2016 등 |
| 멈춘 화면 없음 | 말을 마친 뒤 1초 안에 '듣고 있어요/생각 중'을 보인다. 3초가 넘으면 한국어로 안내한다. 첫 소리는 체감 약 2초가 목표다 **(팀 목표, 실측 아님)** | P2 |
| 침묵·한국어 답 처리 | 침묵 8초 뒤 힌트, 15초 뒤 질문 반복, 25초 뒤 따라 말하기로 바꾼다. 한국어로 답하면 "in English, please?"를 한 번 묻고 영어 답을 화면에 보인다 | [03] §2-3 |
| 접근성 | 질문 자막 18px 이상, 하단 중앙에 큰 마이크 버튼(56px 이상 권장), 상태를 한국어 글자로 표시, 주요 버튼 3개 이하, 자막은 기본 켜짐 | NFR-08, S7·S11 |
| 장면 순서 | **입국심사**(질문 순서가 거의 고정이고 5개 상황 모두 `ask` 가 있어 대본 이탈 위험이 가장 작다) → **교통**(Q3 7/11) | P6, Q3 |
| 개인정보 | 원본 음성은 저장하지 않는다. 받는 곳(Google 등)을 고지하고 동의를 받는다 | NFR-05, FR-13 |

**Should:** 식당·호텔 장면 · 마이크가 없을 때 답을 눌러 고르기 · 한 장면 3~5턴, 2분 이내 · 같은 장면 다시 · 실제 여행 도시를 대사에 넣기.
**Could:** 응급은 검수된 고정 문장의 1단계 스크립트만, AI 자유 대화 없음 · 역할 이름으로 장면 고르기.

**보여 주지 말 것:** 발음 점수(지금 점수는 '단어 일치'이지 발음 점수가 아니다) · 등급 · "입국 거절"·"통과" 같은 결과 · 대화 중 빨간 표시 · 고칠 점 여러 개.

## 4. 어떻게 만드나 — 권장 아키텍처와 단계 ([02](02-tech.md))

| 후보 | 요지 | 판단 |
|---|---|---|
| **A** 브라우저 → Gemini Live 직접 + 임시 토큰 | 지연이 가장 짧다(약 1초 **[추정]**). 장기 키는 서버에만 둔다. 다만 단일 전사라 교차검증 채점을 할 수 없다 | **2단계** |
| **B** FastAPI WebSocket 프록시 | Render 무료 단일 인스턴스라 스핀다운·재배포 때 모든 세션이 끊긴다. 지연과 공수도 가장 크다 | **채택 안 함** |
| **C** 턴 단위(녹음 → `/speak-check` → Gemini 텍스트 → 음성) | 지금 코드와 `talk` 데이터를 그대로 쓴다. 교차검증 채점과 동의를 유지하고, 브라우저 호환성이 가장 넓다. 지연은 수 초 **[추정, 실측 필요]** | **1단계** |

**단계**

| 단계 | 내용 | 비고 |
|---|---|---|
| **0. 선행 조건** | 5절의 약관·고지 문제를 정리한다(유료 등급 전환, 국외 이전 고지, 18세 확인 방식 결정) | 실시간 기능보다 먼저 |
| **1a. 스크립트 회화** (AI 호출 0회) | 회화 연습 시트에 '대화하기'를 추가한다. 흐름은 `ask` 음성 → 내 답 녹음 → `/speak-check` → `replies[i]` 음성 → `next` 녹음 → 끝난 뒤 요약이다. 서버가 없으면 채점 없이 진행한다 | 프론트만 바꾼다(`app.js`). 6절 ①의 음성 파일을 쓴다 |
| **1b. 자유 응답** | 대본과 다르게 말해도 이어지게 한다. 새 `/talk/turn` 에 `heard`·시나리오·이전 턴을 보내면, Gemini 텍스트가 다음 대사와 한국어 뜻, 종료 여부를 JSON 으로 돌려준다. 입국·세관 **규정** 대사는 검수된 고정 풀에서만 쓴다 | `backend/app/talk.py`. 동의 문구 1줄 추가 |
| **2. 실시간(베타)** | 기능 감지(AudioWorklet·getUserMedia·인앱 여부)를 통과한 브라우저에서만 켠다. 서버는 `/talk/token` 으로 모델과 시스템 지시를 잠근 일회용 토큰을 발급한다(`uses:1`, 6분 만료). 점수는 없고, 끝난 뒤 `/talk/feedback` 으로 텍스트 피드백만 준다 | 안 되면 C 로 돌아간다. iOS·카톡을 실기기로 확인한다 |

시스템 지시 골격(역할, `talk` 로 채우는 시나리오, 천천히·짧은 턴, 요청할 때만 한국어, 이탈 시 역할을 유지한 채 되돌리기, `end_roleplay`)과 바꿀 파일 목록은 [02](02-tech.md) §3에 있다.

## 5. 지금 서비스에도 있는 문제 (실시간 기능과 별개)

조사 중에 현재 코드와 문서에서 발견했다. 아래는 **코드로 확인한 사실**이다. 법적 판단은 자문이 필요하다.

| # | 사실 (확인한 위치) | 의미 | 제안 |
|---|---|---|---|
| ① | 말하기 동의 창 문구가 "무료 등급 API에서는 Google이 전송된 내용을 제품 개선에 사용하고 사람 검토자가 읽을 수 있어요"라고 안내한다(`mockup/app.js` 동의 창) | 무료 등급을 쓰고 있을 수 있다. 무료 등급 약관은 "개인 정보를 제출하지 말라"고 하고, 목소리는 개인정보다 **[확인, 04 §1 #1·#10]** | 결제가 연결된 프로젝트(유료 등급)로 옮기는지 **팀이 확인**한다 |
| ② | 저장소 `docs/`·`mockup/` 에 개인정보 처리방침 문서가 없다 | 말해보기는 이미 음성을 미국 회사(Groq·AssemblyAI·Google 등)로 보낸다. 국외 이전은 별도 동의를 받거나 처리방침에 공개해야 한다 **[확인-조문, 04 §1 #4·#5]** | 처리방침을 작성하고(수탁자: Google, Groq, AssemblyAI, Render, Firebase …) 국외 이전 고지를 넣는다 |
| ③ | `/speak-check` 는 로그인(토큰) 없이 부를 수 있다(`backend/app/main.py`). 호출 제한은 IP 기준이다 | 프록시 설정에 따라 모든 사용자가 한 IP 로 묶일 수 있다 **[04 §4]**. 실시간 토큰 발급까지 이렇게 열어 두면 비용 위험이 크다 | 새 `/talk/*` 는 Firebase 로그인과 사용자(uid) 기준 한도를 **처음부터** 요구한다 |
| ④ | `weakDecision` 은 `sentence.ai !== true` 이면 `'none'` 을 돌려준다(`mockup/ai.js`). `data.js` 의 공통 문장에는 `ai: true` 가 없다 | 공통 30문장은 점수가 낮아도 복습 목록에 저장되지 않고, 저장 제안도 뜨지 않는다. 이 문장으로 만든 롤플레이는 복습과 이어지지 않는다 **[03 §4]** | 의도한 제외인지 **팀이 결정**한다. 바꾼다면 사용자가 직접 고르는 저장을 권장한다 |
| ⑤ | 탈퇴 실패 시 최근 로그를 봉인하는데, 가리는 대상이 자격증명뿐이다(`backend/app/evidence.py`) | 대화 자막을 로그에 남기면 봉인본에 그대로 들어간다 **[04 §0·§2.4]** | 대화 내용은 로그에 남기지 않는다 |

## 8. 팀이 정할 것

1. 유료 등급 전환과 처리방침·국외 이전 고지 (5절 ①②)
2. 이용 연령: Gemini API 약관은 18세 이상이다. 실시간 회화를 18세 이상 자기 확인으로 막을지 정한다 ([04] §1 #6)
3. 공통 문장을 복습 목록에 넣을지 (5절 ④)
4. 1a 정적 음성의 TTS 공급자와 라이선스 (6절 ①)
5. 실시간 동의를 기존 말하기 동의와 분리할지 ([04] §2.2 초안 있음)
6. 대화 자막 보관 여부와 기간 (제안: 원본 음성은 저장하지 않음, 자막은 문서 안 필드에 30일)
7. 지연 목표(체감 2초)를 팀 목표로 확정할지

법률 자문용 질문(처리위탁인지 제3자 제공인지, 유출 통지 기한 등)은 [04] §6에 있다.

## 10. 한계

- 표본이 작다(n ≤ 11, 중복 가능). 모집 경로가 하나라 스스로 고른 사람들일 수 있다.
- 공개 통계의 상당수는 원문 보고서가 아니라 기사 재인용이다 **[2차]**.
- 가격과 한도는 2026-10-20 기준이다. 누적 과금 방식처럼 원문을 다시 확인해야 할 항목이 있다.
- 말하기 불안은 측정한 적이 없어 가설로 다룬다.
- AI 대화 상대의 효과에 대한 독립 연구는 대부분 스크립트형·제한형 시스템을 다룬다. 경쟁 서비스의 효과 주장은 대부분 자사 발표다 ([03] §5).
- 카톡 인앱의 마이크·AudioWorklet 동작과 iOS 출력 음량 문제는 **실기기 확인 전**이다.
