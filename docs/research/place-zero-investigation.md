# 장소 목록 0건 조사

## 1. 확인 상태 및 결론

11/2 작성된 초기 조사(가설 단계)에서 더 나아가, 11/8 실제 위키보이저 API 및 파서(`wikivoyage_parse.py`) 검증을 통해 **도시 장소 목록 0건 문제의 근본 원인을 규명**했습니다.

- **기존 가설 기각**: "위키보이저 도쿄 문서에 '가볼 곳' 섹션이 없어서 비었다"는 가설은 사실이 아닙니다. 도쿄 문서에 See 섹션은 정상적으로 존재합니다 (Level 2, 4,592자).
- **진짜 원인**: See/Do 섹션은 존재하지만 그 안에 **구조화 리스팅 템플릿(`{{see}}`, `{{do}}` 등)이 0개**입니다. 도쿄 상위 문서는 산문(prose)과 30개 구(district) 문서 링크(`[[Tokyo/Shinjuku|Shinjuku]]` 등)로만 구성되어 있습니다.
- **공항/대사관만 노출되는 이유**: 도쿄 상위 문서 전체에서 리스팅 템플릿이 존재하는 섹션은 Get in(`{{go}}` 7개, 공항·역·페리)과 Cope(`{{listing}}` 97개, 대사관·병원 등)뿐입니다. 파서가 리스팅 템플릿만 장소로 수집하기 때문에, 화면에 공항과 대사관만 남는 현상이 정확히 일치합니다.
- **실제 데이터 위치**: 도쿄의 실제 관광 장소 248건은 `Tokyo/Chiyoda`, `Tokyo/Shinjuku`, `Tokyo/Asakusa` 등 30개 하위 구 문서에 정상 수집되어 있습니다.
- **일반화된 패턴**: 구 문서 체계를 쓰는 대도시 37곳 중 **23곳(62%)**이 상위 문서 See 리스팅 0건입니다(런던, 로마, 베를린, 방콕, 싱가포르, 홍콩, 타이베이, 오사카, 부산 등). 특정 도시의 예외가 아니라, 대도시 하위 구 문서 구조를 반영하지 못하는 파서의 구조적 추출 문제입니다.

| 대상 | See 리스팅 수 | Do 리스팅 수 | 비고 |
|---|---|---|---|
| **Tokyo (상위 문서)** | **0** | **0** | Get in 7개(`{{go}}`), Cope 97개(`{{listing}}`)만 존재 |
| **Tokyo 30개 구 문서 합계** | **248** | — | Chiyoda 15, Shinjuku 16, Roppongi 15, Asakusa 10 등 |

### 도시 37곳 비교 분석
- **상위 문서 See 리스팅 0건 (23곳, 62%)**: 도쿄, 부산, 교토, 오사카, 런던, 로마, 마드리드, 베를린, 암스테르담, 빈, 이스탄불, 리스본, 방콕, 싱가포르, 홍콩, 타이베이, 쿠알라룸푸르, 자카르타, 시드니, 멜버른, 밴쿠버, 토론토, 두바이
- **상위 문서에 리스팅 존재 (14곳)**: 아테네(57), 하노이(36), 멕시코시티(33), 치앙마이(29), 파리(27), 후쿠오카(25), 삿포로(25), 호치민(24), 카이로(9), 마닐라(5), 프라하(4), 뉴욕(3), 서울(1), 바르셀로나(1)

*결론: 관광지가 한 문서에 모여 있는 중소도시는 정상 동작하지만, 하위 행정구역 문서로 분리된 대도시는 상위 문서만 파싱할 경우 필연적으로 0건이 반환됩니다.*

## 3. 코드 분석 (`backend/app/research/`)

1. `wikivoyage_parse.py`:
   - `listings()` 함수는 `TEMPLATES`에 매핑된 정규 템플릿(`{{see}}`, `{{do}}`, `{{eat}}`, `{{drink}}` 등)만을 장소로 파싱합니다.
   - 산문 링크(`[[Tokyo/Asakusa|Asakusa]]`)나 일반 텍스트 내 추천 장소는 추출 대상에서 제외됩니다.
2. `sources/wikivoyage.py`:
   - `_placeish(ls) < DISTRICT_IF_FEWER` 조건 시 `wp.districts(page["text"], page["title"], limit=2)`로 하위 구 문서를 최대 2개 조회하는 로직이 있으나:
     - `limit=2`로 제한되어 대도시의 대표 명소를 충분히 포괄하지 못함
     - `{{Regionlist}}` 템플릿 명명 규칙이 도시마다 다르거나 없는 경우 하위 구 인식이 누락됨
3. `nodes.py` (`city_places`):
   - 위키보이저에서 장소가 부족하면 대체 소스 체인(`wikivoyage_intl`, `tourapi`, `wikidata_places`, `google`)을 순회하지만, 상위 위키보이저가 빈 배열을 반환하고 대체 소스마저 쿼리 매칭에 실패하면 최종 장소 목록이 0건으로 고착됩니다.

## 4. 복구 및 개선 제안

1. **단기 (안정적 복구)**:
   - 위키보이저 상위 문서의 장소 리스팅이 0건이거나 임계치 미만일 경우, 하위 구(district) 문서 탐색 대상(`limit`)을 2개에서 주요 구 5~8개 수준으로 현실화하고 캐싱.
   - `Districts` 섹션 파싱 시 `{{Regionlist}}` 외에 일반 위키링크(`[[도시명/구역명]]`)도 하위 구 후보로 인식하도록 보강.
2. **중장기 (진단 및 UI 대응)**:
   - 빈 결과와 공급자 오류를 구분하여 응답 메타데이터에 `fallback_used`, `district_count`, `source_page` 필드 기록.
   - 결과가 0건일 때 화면에 "해당 도시는 세부 구역별 정보로 구성되어 있습니다" 등 안내 문구 제공 및 대체 추천 트리거.
3. **한국어 위키보이저 주의**:
   - `ko.wikivoyage.org`는 인큐베이터 상태로 주요 도시 문서가 대부분 1~2줄 골격(리스팅 0건)이므로, 다국어 전환 시 소스로 사용하면 전 도시가 0건이 되는 치명적 결함이 발생하므로 영어판 우선 유지가 필수적임.

## 5. 발표용 3줄 요약

1. 도쿄의 장소 0건 문제는 '섹션 누락'이 아니라, **대도시 문서 특성상 장소 템플릿이 30개 구 하위 문서(248건)에 분산**되어 있어 발생한 구조적 현상입니다.
2. 전 세계 주요 대도시 37곳 중 **62%(23곳)**에서 동일하게 상위 문서 리스팅이 0건으로 나타나므로, 특정 도시 버그가 아닌 일반화된 파서 설계 과제입니다.
3. 상위 문서 리스팅 부재 시 하위 구 문서를 연계 수집하는 폴백 로직을 보완하여 근본적으로 해결할 수 있습니다.
